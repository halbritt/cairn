## 1. Source-Level Review of `swarm-view-design.md`

### 1.1 What holds up
- **Kernel boundary:** Keeping Cairn in store-and-deliver mode ("stores and delivers; does not act"), organized around agents rather than mirrored Plane issues, avoids rebuilding an orchestrator or repeating the retired Work View board (`CAIRN-837`).
- **Process isolation:** Serving `cairn swarm serve` from a separate loopback process with the local operator channel keeps `/proc` and Herdr host reads plus operator authority out of `cairn serve`.
- **Zero prompt growth:** Out-of-band PostgreSQL and Herdr reads add no hooks, subscriptions, or recall overhead unless the owner explicitly invokes an operator verb (`CAIRN-808`).
- **Commit-ordered event log invariant:** Every production `INSERT INTO cairn.agent_event` path today—[core/agent_events.go](../../core/agent_events.go), [core/agent_event_reissue.go](../../core/agent_event_reissue.go), [core/agent_wait_scheduler.go](../../core/agent_wait_scheduler.go), [core/agent_stopped_backlog.go](../../core/agent_stopped_backlog.go), and [core/overdue_checkpoints.go](../../core/overdue_checkpoints.go)—acquires `pg_advisory_xact_lock` on `"agent-events:" + repo` and holds it to commit. The `position > N` SSE cursor in `CAIRN-829` rests on an invariant that holds in current source.

### 1.3 Strategic gap: human legibility vs. swarm capability
`swarm-view-design.md` addresses **human situational awareness**, removing one bottleneck when overseeing 10–30 panes. Four **agent-side swarm bottlenecks** remain outside its scope:
1. **Voluntary ceremony tax:** Campaigns, ledger items, and waits rely on agents remembering to invoke `cairn team`, `cairn ledger`, and `cairn wait`; under context pressure agents skip them, leaving the view sparse.
2. **Turn-boundary blind window:** Browser operator actions commit in milliseconds, whereas coding harnesses run 5–15 minute turns and sample Cairn inboxes only at turn boundaries—allowing a superseded session to write stale notes and push to `origin/main` before polling.
3. **Global collection lock contention:** Because one `repo` value (`$HOME/git/cairn`) backs all projects on the host, every publication, ledger write, subscription update, and handoff across *all concurrent swarms* serializes on a single PostgreSQL advisory lock (`"agent-events:" + repo`).
4. **Shared-memory and trunk contention:** `cairn.agent_event` requires a permanent `memory_record` (`FOREIGN KEY(record_id, version)`), feeding transient coordination chatter into durable storage and semantic indexing, while `git-land` lacks a passive Cairn slot to prevent $O(N^2)$ rebase-and-retest stampedes on `origin/main`.

## 2. ADHD Exploration: Alternatives and Enhancements

### 2.4 Focus: Top 3 Mechanically Deepened Branches

#### Branch 1 (`I29`, `9.04` ★) — Transitive-Wait Demurrage Port Congestion Board
- **Sketch:** Cairn links `cairn.agent_wait` predicates (`request_response`, `response_group_closed`) to upstream `cairn.agent_delivery` leases and `cairn.campaign_ledger_item` rows (`assignment`, `blocker`, `hold`) via explicit correlation and `blocked_by` references so PostgreSQL traverses cross-session and cross-campaign dependency edges without parsing event bodies. During `cairn swarm serve`'s 2-second `REPEATABLE READ` snapshot transaction, one `WITH RECURSIVE` query with PostgreSQL `CYCLE` detection walks from every active `agent_wait` row through unfulfilled responders up to root bottlenecks—unacknowledged `agent_delivery` leases, unsettled `hold`/`blocker` ledger items, and unacted owner-inbox deliveries. Preserving `"stores and delivers; does not act"` with zero background tickers or write amplification, the query computes each bottleneck's live burn rate (`COUNT(DISTINCT waiting_session_id)` in `agent-s/s`) and cumulative demurrage (`SUM(EXTRACT(EPOCH FROM (snapshot_now - GREATEST(bottleneck_since, wait_path_since))))` deduplicated per `(bottleneck_id, waiting_session_id)`) functionally from existing timestamps. Swarm View orders its primary board by live burn rate and accrued fleet-idle demurrage, placing human-gated holds and wedged agent leases on one commensurate cost scale while collapsing zero-demurrage healthy sessions into a compact underway strip. Expanding any congestion row unfolds its transitive `agent_wait` tree across all five harnesses and binds inline `settle`, `supersede`, `wait-cancel`, and `send` verbs directly to that root bottleneck.
- **Load-bearing risk:** Causal graph discontinuity across turn-boundary inbox drains: an `agent_delivery` lease closes as soon as an intermediate coordinator drains its inbox at a turn boundary even though the caller's `agent_wait(request_response)` remains open while that coordinator reasons or delegates downstream. If the recursive query traverses only unacknowledged `agent_delivery` rows, transitive demurrage severs at the first acknowledged coordinator hop; conversely, bridging blindly through `agent_session` without explicit `parent_request_id` or `assignment_id` attribution cross-contaminates unrelated subtrees on a multi-tasking lead.
- **First concrete step:** Add a SQL migration and `make test-integration` suite against a disposable PostgreSQL cluster linking `cairn.agent_wait` through unfulfilled request `cairn.agent_event` responder bindings and `cairn.campaign_ledger_item` `blocked_by` references, implementing a read-only `cairn.swarm_congestion_snapshot(as_of timestamptz)` recursive `CYCLE`-safe query verified on multi-hop chains, acknowledged intermediate coordinator hops, diamond `response_group_closed` fan-ins, and mutual wait cycles.
- **Child ideas (recombined):**
  - *BAR aperture deadweight weighting (hybrid with `I16`):* Weight each stalled `agent_wait` node's burn rate by the scarce reservations it holds while parked (`role/<campaign>/root` ownership or write-exclusive Base Address Register file/symbol apertures) rather than counting every idle session uniformly at `1.0 agent-s/s`.
  - *Demurrage-denominated lease budgets (hybrid with `I18`):* Denominate exclusive `agent_delivery` and `role/<campaign>/root` lease lifetimes in accrued downstream `agent-seconds` since the holder's last turn-boundary progress receipt, letting unblocked leaf workers run long builds while a wedged coordinator starving ten waiters sheds its role rapidly.
  - *Congestion-embargo admission gate (hybrid with `I11`):* Once a coordinator or campaign crosses a live demurrage watermark, embargo new `VC_REQUEST` spawns (`Berth Congested`, returning the root bottleneck ID) while letting `VC_COMPLETION` settlements and `VC_CONTROL` operator verbs bypass on reserved credits.
  - *Demurrage-ordered `integration_slot` queue (hybrid with `I13`):* Order a repository-wide `integration_slot` merge queue by each waiting branch's live downstream `agent_wait` burn rate rather than FIFO so commits unblocking stalled campaign trees land on `origin/main` ahead of zero-waiter leaf refactors.
  - *Durable `settled_demurrage_agent_seconds` receipts (unlock):* Stamp cumulative demurrage onto closed deliveries and settled ledger items to gate external `agent-board` interruptions by `agent-minutes` burned and build an empirical Pareto bottleneck ledger for `retro`.

#### Branch 2 (`I06`, `8.83`) — Asynchronous Clock-Domain Crossings & Stale-Epoch Admission Fencing
- **Sketch:** Every `cairn.agent_session` (and active `cairn.campaign_ledger_item` binding) gains two monotonic PostgreSQL `BIGINT` counters—`target_epoch` in the fast operator/control clock domain and `latched_epoch` in the slow harness turn-edge clock domain. When an operator invokes `supersede`, `settle`, `wait-cancel`, or `send --fence` in `cairn swarm serve`, the Go handler records the `cairn.agent_event` (`notice_supersedes`), updates `cairn.agent_delivery` (`control_at`, `control_by`, `code`), and increments `target_epoch` on every affected session in one atomic transaction while leaving `latched_epoch` unchanged. `latched_epoch` advances only when an authenticated turn-boundary inbox drain (`inbox next` / `cairn.agent_session_poll`) delivers all pending control notices up through `target_epoch`, stamping `latched_at` with zero prompt growth. Whenever `target_epoch > latched_epoch`, Swarm View's 2-second snapshot renders the session in explicit `unlatched-skew`—showing the pending control verb and elapsed skew since `control_at`—rather than painting the override as absorbed while an LLM is mid-turn. Simultaneously, Cairn admission-fences store-owned mutations (`cairn_remember`, outbound `agent_event` publication, and `campaign_ledger_item` transitions) by asserting `latched_epoch = target_epoch`, rejecting stale-epoch writes with `stale_control_epoch`, while `git-land` runs a Cairn epoch-preflight right before rebasing and pushing `origin/main`.

#### Branch 3 (`I11`, `8.43`) — PCIe Virtual Channels & Receiver-Context Flow-Control Credits
- **Sketch:** Cairn partitions `agent_event` admission and turn-boundary `agent_delivery` selection into four PCIe-inspired Virtual Channels—`vc_admin` (operator control verbs: `send`, `supersede`, `settle`, `wait-cancel`), `cpl` (replies, settlements, and `wait_notice` wakes bound to `081` closure-reservation tokens), `np` (new work requests and blocker escalations), and `p` (advisory notices)—derived strictly from store-owned principal and reservation metadata rather than caller-supplied flags. In PostgreSQL, each recipient session maintains an explicit `np` and `p` byte-credit ledger computed from its `CAIRN-816` `bytes_injected_since_compaction` ceiling minus unacknowledged `agent_delivery` payload bytes, while `vc_admin` and `081`-backed `cpl` carry guaranteed bypass credits so loop-closing completions and human overrides never stall behind request floods. When `event-admission` (`080`–`084`) evaluates an `np` or `p` event targeting a credit-exhausted coordinator or `role/<campaign>/root` inbox, Cairn prevents unbounded FIFO queueing by parking the sender on a credit-replenishment `agent_wait` condition or returning a structured `credit_backpressure` admission outcome with zero prompt growth. At each turn-boundary inbox drain, Cairn's Go selector schedules strict priority with byte-budget packing (`vc_admin -> cpl -> credit-fitted np -> p`), replenishing credits when deliveries are acknowledged, `compaction_count` increments, or a `094` coordinator handoff completes. - **Load-bearing risk:** Opaque harness context consumption and silent mid-turn stalls cause credit drift: `CAIRN-816` tracks Cairn-injected bytes and reported compactions rather than harness-local tool output (file reads, test logs, reasoning tokens) across Codex, Claude Code, Agy, OpenCode, and Hermes, so a coordinator can exhaust its real model window while Cairn still advertises positive `np` byte credits—or wedge mid-turn leaking `np` credits unless credit leases expire on missed turn-progress receipts and `cpl` bypass is relationally enforced via `081` closure tokens.
- **First concrete step:** Add a PostgreSQL migration and store-layer classifier in Cairn's `event-admission` and inbox-delivery path assigning every `agent_event` a store-owned `vc_class` (`vc_admin`, `cpl`, `np`, `p` derived from authenticated operator channel and `081` closure-reservation linkage), ordering turn-boundary drains as `vc_admin -> cpl -> np -> p` under a per-turn byte cap tied to `CAIRN-816` counters, and verifying deadlock-free `cpl` and `vc_admin` delivery at zero `np` credits via `make test-integration`.
