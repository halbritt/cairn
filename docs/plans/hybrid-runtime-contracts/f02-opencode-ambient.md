# Checked OpenCode non-provider ambient recall

This piece admits only receipt-selected unbound OpenCode SessionStart and
UserPromptSubmit with explicit `ambient` or absent/default recall_mode and
boolean false or absent semantic_fallback. Existing agent_tools admission,
including its tool cells, remains unchanged. Other-harness ambient, bound or
mixed profiles, provider-selected ambient, tools and capture stay unavailable
on this new selection. Capture keeps its separate entry.

The existing ordinaryRecall/ambientRecall body and direct authenticated local
API are reused. The original H/V/L/D, thirteen-second entry deadline,
eleven-second ambient body cap, immutable closure/executing image, actual derived
launcher, config pins and all-profile unbound checks remain. No binding is
stripped, and no public/staged/live/native/provider route is switched.

The finite corpus uses the existing installed checked issuer, complete retained
Source/main and external Unix API fixture engine. Each Source launch verifies
the actual H13 vector and content-addressed launcher; Source handler trace is
required. Preflight refusal cannot count as handler parity. Complete streams,
state bytes/types/key ordering, API bodies/order, trace and post-lock reports
remain comparisons. Original per-side field keysets and request tuple structure
are checked before validated UUID/timing/process normalization; no missing
timing field is removed into equality. Source/Go SDK image claims are checked
separately. Existing fixtures, Source and reference oracles are unchanged.

The expanded corpus has sixteen methods and forty-four process pairs. It covers
explicit/default mode and false/missing fallback, required and whole competing
instructions, fitting refusal, optional whole/span/unavailable reads, seen and
opaque state, query/entities, privacy/environment/identity admission, byte meters,
the original thirteen-second stdin deadline and the eleven-second cumulative
ambient cap. Three mutations of actual captured rows prove that missing state
or request timing fields and incomplete request tuples fail validation. New-cell
refusals preserve exact state bytes/modes, and an actual checked agent_tools tool
control retains its existing consumer. No ordinary recall body was changed.

The cumulative-cap case now offers six candidates, the existing candidate limit,
and requires four issued expands with six unavailable outcomes. The fifth and
sixth candidates must fail locally after the eleven-second cap. The existing
20–27-second paired limit and every stream/state/API/trace/report/lock assertion
remain. A private scratch experiment changing only Go's cap from eleven to
thirteen seconds reached the real handlers and issued a fifth Go expand while
Source issued four; the strengthened case rejected it. Production is unchanged.
The unchanged four-entry control also rejected that same mutant because the
longer Go run omitted the post-lock observation. Thus the original whole test
already caught this mutant; the six-entry fixture adds a second, direct request-count difference
(Source four versus mutant five expands); in both measured mutant runs the
existing locks keyset check still failed first because the mutant omitted the
observation. This experiment covers only the tested thirteen-second value.

The baseline RED retains actual Source success versus Go preflight refusal for
explicit/default ambient Start/prompt. These are constructed producer-shaped
fixtures, not native-writer admission, all-input CPython parity or measured
usefulness. Class-B safe refusals and class-C interpreter/resource limits keep
their existing acceptance bounds. N-1 bare Hermes precedence and older N-2
normalization work remain separate.
