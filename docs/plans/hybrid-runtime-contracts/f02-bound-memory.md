# Direct checked bound memory consumer

The private `IMAGE memory --receipt ...` entry runs receipt-selected Codex
`agent_tools` SessionStart/UserPromptSubmit recall and the 150-second capture
cells: Codex PreCompact/Stop and Claude PreCompact/SessionEnd. Each invocation
reaches the actual F04 `ResolveActivation` decision. The hook stager selects these
supported bound rows through the checked entry and retains their Python launchers
for reverse selection. Live apply and the public lifecycle command remain held.

V is the actual process argv. L is derived from its exact shell-quoted bytes in
the persistent content-addressed launch root. Receipt, whole retained closure,
role/alias/config selection and the selected/running image are checked before
configuration use. The executable descriptor remains held through the body.
The entry captures D once before preflight, using the independently selected
13-second recall or 150-second capture budget. No external V, D or FD is accepted.

The selected configuration snapshot and raw event determine the internal
HookInvocation. Digests come from checked bytes, not event assertions. The actual
activation writer runs once; the retained caller's final profile check reuses
the original parent snapshot without a second admission or activation. Enabled callbacks validate every profile,
manifest and final pin before entering the existing RunStart body. Cached true
decisions retain the final-pin requirements even under a disabled manifest.
The frontend rechecks enabled bindings after recall, reusing the same parent
config bytes. A late coordinator-pin failure suppresses output and preserves
committed grant/state charges, including proven required-context refusal.

Source admission excludes capture from inbox activation before manifest access.
That false decision does not skip capture or reinterpret the generation as an
unbound installation. The original config keeps its binding; only an internally
resolved invocation may enter the existing capture body. Explicitly unbound
OpenCode Start/prompt continues to use the unchanged VerifyOrdinary validator.

The first process corpus runs the actual R02 installer, complete checked Source
frontend/verifier and direct Go launcher against disposable configs and an
authenticated synthetic Unix API. It compares public streams/exits, normalized
state, ordered API payloads and actual post-lock reports. Ordinary checked Source
already delegates recall to the existing Go body; the retained literal Source
body remains covered separately by the existing F02 Start/prompt corpus.

The expanded paired corpus covers enabled/disabled and cached activation,
changed or incompatible profiles, preservation of the parent snapshot, late
post-body refusal with committed required grants, canonical/malformed native
identity, account/privacy exclusions, both locks, capture CAS and concurrent
recall state, failed replacement and retry. Go-only negatives reject external
deadline/vector/descriptor/authentication flags and reach the original deadline
with stdin still open, before API or state effects.
Actual owner-only invocation traces are compared on success, activation failure
and late required refusal. Only validated process IDs, invocation IDs and timing
fields differ; activation stage/error labels and required outcomes retain Source.

Configured bound capture calls the existing provider/selection implementation
through runCapture. Actual checked 150-second Source/Go pairs cover null
selection, ordered note/checkpoint saves, prewrite refusal, partial confirmed
writes, CAS conflict, selector failure, cleanup and post-lock reporting. The
deadline pair holds stdin for 130 seconds before entering retrieval and a
35-second local selector: the original entry deadline must stop the complete
invocation near 150 seconds without a write or committed capture state.
Only the external selector and authenticated Unix service are synthetic.
Producer qualification and final composition review remain separate gates.

Native turn UUID syntax, including the Source's accepted zero UUID, is metadata.
Extra event agent/execution/lease/expiry fields do not authorize an inbox claim.
Actual ownership, execution freshness, lease and delivery policy remain with
Coordination; this consumer neither validates a fabricated delivery nor creates
a native session. The synthetic API profile is the authenticated store boundary.

Inputs retain the owner's three classes: producer-shaped supported calls are
paired with Source; malformed inputs must refuse safely without inventing
authority; interpreter/resource and unsupported-cell cases are explicitly outside
equivalence. No all-input CPython or host-native acceptance is claimed.

Only independently generated request UUIDs and validated wall/elapsed timings
are normalized. The fixtures record the independently pinned Source closure,
receipt and executing Go image. Bound Claude recall, other harnesses and tool
events remain explicit unavailable cells in this new entry. Capture body/provider
construction and native delivery policy retain their existing owners; no new
provider parser, live provider call, installation, activation or acceptance is
claimed by this source slice.
