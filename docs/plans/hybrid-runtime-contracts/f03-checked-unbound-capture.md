# Receipt-checked unbound capture

The private lifecycle image accepts `IMAGE memory-capture` followed by the
existing eight selection flags: `--receipt`, `--receipt-sha256`, `--role memory`,
`--entrypoint memory.py` (or a receipt alias), `--config`, `--hook-timeout 150`,
`--launch-root`, and `--shell`. Original event bytes remain on stdin. The public
`cairn lifecycle` command and staged hook rows retain their existing selection.
Release owns any later join of this consumer into installed rows.

The host captures entry time before preflight and derives one original deadline
from H150. The actual argv, including the `memory-capture` token, defines V and
the exact content-addressed launcher L. No external deadline, vector, descriptor
or authentication flag is accepted. The executing image descriptor remains
held through input, capture, reporting and return.

`binding.VerifyUnboundSelection` verifies the same complete immutable receipt,
closure, alias, image, disabled manifest, ordered descriptors and every pinned
profile as the existing ordinary verifier, preserving its controlled-data failure
phases. All one to eight coordination profiles and the memory profile must be
unbound. Mixed or opted-in profiles refuse; there is no binding removal,
activation writer or disabled-staging exception. This core does not authorize
any harness or event. The existing H13 verifier can adopt it in its owner's
separate lane; this change leaves that owned file untouched.

After verification, the capture host admits exactly the Source producer cells:
Codex PreCompact/Stop, and Claude/OpenCode/Hermes PreCompact/SessionEnd. Agy has
no memory producer row. Codex SessionEnd, other-harness Stop, recall/tool events
and invented event names are unavailable through this private ABI. The original
config, decoded event, cwd and environment then enter `memoryhook.RunOrdinary`.
Its admission, privacy/account checks, capture body, selector, write identities,
locks, state CAS, transcript markers and post-lock reporting remain unchanged.

The corpus in `scripts/test_f03_checked_unbound_capture.py` uses the real R02
installer and complete installed Source verifier against the new Go entry with
the same receipt. Only the Unix API and external selector are synthetic. It
retains streams, exits, ordered writes and state, validates nondeterministic
request/timing fields before normalization, and checks Source closure and Go
image attribution independently. Producer-shaped inputs require paired parity;
malformed inputs require safe stable refusal; resource/interpreter limits remain
documented exclusions under owner decision `98d46758/v1`.

The corpus exercises every supported producer cell with substantive selection,
null and existing-record no-op selections, ordered and partial writes, retry
reconciliation, CAS/replace failure, transcript append/truncate/missing cases,
owner-text filtering, duplicate/stop coalescing, crash lock release and post-lock
reporting. It changes each of eight pinned coordinator profiles independently
and refuses changed code, receipt, image, launcher and profile selections before
body effects. Source SDK identity follows the actual selected alias: canonical
and `.py` aliases report the checked member digest; a non-`.py` alias reports an
unknown implementation ID. Go reports its independently checked executable
digest. These differences are asserted explicitly, rather than normalized away.

The original-deadline pair leaves stdin open for 130 seconds, then enters real
retrieval and a 35-second synthetic selector. Both actual processes must stop
between 148 and 162 seconds without a write or committed capture state. This
tests the new caller's original H150 allowance across stdin and body work.
The existing input cap is 1 MiB; larger input refuses before body effects. Receipt,
member, config, selector-output and subprocess limits remain those of the reused
components. Legacy lossless integer decoding and Source argv/interpreter limits
do not acquire an all-input parity claim through this entry.

The bounded N-1/N-2 review follow-up carries five unchanged
`CaptureBoundaryTests` methods in `CheckedUnboundBoundaryCoverageTests`:
invocation trace identity/phase/stage/outcome/context, final commit wait and
timeout, preparation failure, invalid dialogue/missing transcript, and ASCII
blank-line handling. Each test is the original function object with its original
name and assertions; malformed inputs retain the owner's class-(b) distinction.
The bound-only missing-manifest test is not an unbound policy test.

The trace fixture observes the actual receipt-config-relative trace file through
a hard link at the unchanged reference method's project-relative path. File
identity is asserted before either real process runs; no trace records are
copied, synthesized or normalized beyond the reference method's allowed fields.
Boundary pairing compares Source/Go lock observations exactly and requires the
hook-owned capture lock to be released. The final-wait case deliberately leaves
the shared lock held by a separate legacy writer during its timeout report; its
observed locked state remains part of the comparison.

This test-only follow-up preserves the prior 64-method qualification and original
H150 proof. It runs only the five newly carried methods; final combined-tree
gates, independent review and integration remain with Foundation.

This is a source construction candidate for the existing Foundation review and
integration path. It establishes neither full CAIRN-319 acceptance nor installed
cutover, provider usefulness, native session policy or permission for production
changes. Rollback retains the existing checked Python launchers.
