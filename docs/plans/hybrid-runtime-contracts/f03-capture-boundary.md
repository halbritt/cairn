# F03 unbound capture boundary

The ordinary `cairn-lifecycle memory --config PATH` entry now reaches a finite
unbound capture body at the actual Source capture events. This frontend owns
admission, event binding, capture/shared locks, a bounded transcript snapshot,
owned-state CAS, status/marker persistence and post-lock capture observations.
It does not enable public lifecycle registration or select a provider.

The reached set is empty dialogue, missing Codex transcript pending,
short Codex Stop, confirmed duplicate and courtesy-only dialogue. The Source
fingerprint includes the literal capture prompt/schema, configured model value
and bounded dialogue. A fingerprint is identity data, not selector execution.
Substantive provider-selected capture stays explicit unavailable and retains the
Source selection. No record save or `saved` status is claimed by this body.
Existing `CommitCaptureSelection` remains a separate component and is unchanged.

The capture lock spans one attempt. The shared session lock covers only initial
state and final commit. The final commit keeps Source’s 50 ms retry cadence
and stops retrying at its remaining deadline; the shared lock helper is unchanged.
Final CAS compares the original binding and exact
presence/values of CAPTURE_STATE_FIELDS, preserves concurrent recall/hint data,
and advances markers only after a successful replace. The capture-meter/2 report
uses the authenticated SDK after both locks release; failure remains best effort.
No selected content, payload identity or metric is authentication.

Memory conversation filtering is implemented locally in capture_dialogue.go.
The existing transcript package implements native custody/recovery evidence and
has no matching memory.conversation export; its contracts/files are unchanged.
Offsets refer to the exact bounded read and distinguish repeated Codex messages.
This does not claim native C/CPython/value-graph construction or all-input parity.

The new process corpus stages the actual complete retained Source bundle and
compares its ordinary disabled /2 path with the real Go entry, using only
synthetic Unix API and transcripts. It asserts complete streams/exits, ordered
state, report requests, owner-only synthetic authorization and separately checked
executing image SHA. Capture timestamps, request UUIDs and measured durations are
validated before normalization. No replacement Source capture body is used.

The process corpus covers capture/shared contention, final commit wait/timeout,
changed binding and absent/null capture fields, concurrent recall/hints,
repeated text and append/truncate offsets, append after snapshot, failed replace
and retry, post-lock report failure, actual supported capture event families,
bounded transcript tails and owner filtering, invocation trace dispositions,
preparation failures without reporting, and redacted unexpected transcript failures. Source timestamps in Hermes output
are the same declared wall-clock normalization as persisted capture status.

Ownership join 0d9c15b1/v1 moves only the obsolete capture row from the old F02
unported table to the new exact missing-OpenCode-transcript pair. That pair resets
the whole state directory independently for Source and Go and verifies both locks
and directory creation, exact KeyError streams, no API calls and no committed
JSON/marker/saved status. Bound/provider/observation/invented-shell rows stay intact.
Unexpected Source exceptions retain Go’s declared redacted diagnostic; ordinary
caught errors keep exact streams and exits. Source/provider/failed F03 and all
other campaign holds remain. This is a finite
frontend construction, not full F03/319/318/R04 or native host acceptance. Same
existing1279 review and lead integration remain required.

The transcript blank-line predicate matches Source bytes.strip: ASCII space,
tab, LF, CR, vertical tab and form feed only. Unicode-space-only records reach
the unchanged JSON decoder and fail; they cannot become empty capture or permit
later dialogue to commit past the invalid record.

For the unsupported substantive Go cell, the actual attempted-capture error
observation remains guarded by capture_observations=True, after both locks and
admission/privacy. It reports error, with no selector, save or successful capture.
A final state read/decode failure has a retained metric-label difference: Go
reports state_commit_error while Source keeps the capture outcome. Both fail
without a new commit; this malformed/environment input residual stays outside
B1's predicate repair and does not establish full F03 acceptance.
