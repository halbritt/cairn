# SDK launch and hosted retrieval source path

The `sdk-hosted-memory/1` profile supplies a source-bound launch path in
`FixedRunOwner`. It is not selected-executable compatibility, measured native
input delivery, physical RSS admission, or CAIRN-107 acceptance. The legacy null
hook-interface declaration still refuses `require_complete`.

`prepare_native_review` reserves its named preparation storage before opening,
copying or parsing sources. `SDKNativeLaunch` holds the exact copied executable
and configuration inodes; it maps only the executable and configuration argument
positions. The fixed service must use that same held Cairn executable and the
prepared socket, token-file path and repository/task/run scope. `start_native`
consumes its once-only launch before validation/effects, requires actual service
readiness, and uses the original native process owner and capture-origin+30s
deadline. Source construction does not require observations of an unstarted
process. Namespace, account, executable selection and launch authorization remain
with the outer runtime owner; no declaration boolean supplies them.

Native `mcp_message` requests use the session's existing bounded reader, exclusive
partial-write stdin owner, original traffic ledger, and the SAME
`MemoryDispatchGate` and fixed command service as callbacks. There are still two
native searches and four shared expansions, never a fresh allowance per request.
The service revalidates native JSON using its fixed policy before the original
command owner launches. Search maps every current `searchArgs` field, including
symbol entities and context pins. Pull preserves the original complete JSON
request. Wrong JSON types refuse before normalization. The incoming 131072-byte
document/graph limits and existing command/process argument limits apply; there
is no extra 8192-byte native-request restriction.

`internal/sdkcontract` lists the source Go server over an in-memory transport
without invoking retrieval. Its committed `trial_sdk_native_tools.json` contains
the complete authoritative retrieval descriptions, field schemas and annotations.
The Go drift test compares the full result to `addRetrievalTools`. The parent
reads only the pinned held snapshot when advertising tools. This preserves
mandatory selected context, complete pull arguments, stale-handle fresh search,
partial spans/openings, competing whole pulls and full-note-before-edit guidance.
It does not certify that a selected external executable was built from this Go
source. Responses retain selected/competing/opening data; CLI-only pull command
strings are removed and the search schema becomes the MCP schema. The adapter
still uses the CLI rendering path, so its CLI-side envelope budget checks remain
in addition to the MCP result check; exact facade byte parity is not asserted.

The fixed producer explicitly establishes nondumpability after exec, before
bootstrap input and socket connection. Linux exec resets that property, so
parent-only setup is insufficient. Original broker credential and nondumpability
guards remain in place. Callback directories are created by the owner with
private permissions, a fresh run root and exclusive request-digest leaves. A native child wait
before terminal stdout has drained is allowed; EOF without a terminal refuses.

## Storage and alias lifetimes

The original limits stay raw 131072 bytes, combined raw+working 512MiB, and total
traffic 4MiB. No original callback or command quote was reduced. The historical
caller-selected preparation quote 65536 still produces the documented failing
136353/153325 sums. It was never a literal minimum in
`prepare_sdk_review_with_resources`; old generated phase tables describe that
fixture, not a universal impossibility result.

The new explicit preparation raw quote is 41985: retained controller wire 8500,
fixed permission bytes 705, four 8192-byte canonical slabs and 12 carry bytes.
Canonical output now uses a fixed slab instead of an overallocating growing
bytearray. The four-slab bound covers the caller's preceding block, yielded
block, encoder piece and generator slab. Source readback/Unicode error copies
fit inside this envelope. Native replies use unbuffered canonical pieces, so no
complete encoded MCP reply is allocated. Request JSON, command stdout, parsed
response data and JSON text remain Unicode/graph working storage. Whole-body
hashing encodes at most 2048 scalars at a time. Result parsing never encodes the
whole retained stdout string. The parent command ticket survives parsing,
serialization, actual reply writes and their returning frames; only the later
retirement turn drops its result aliases and releases that ticket. Failed or
interrupted operations retain/quarantine their allocations.

Preparation working storage is 64MiB for bounded source/controller graphs,
terminal/offer metadata and canonical traversal. Command result graphs and text
remain under their original 64MiB parent quote until retirement. These are
explicit source storage reservations, not measurements of interpreter/compiler
internals, kernel queues or selected native executable RSS. Existing engine
compilation/transitive runtime backing and cumulative callback working retention
still need whole-workload validation; a successful logical bank is not proof of
physical fit.

With preparation 41985, session 2566 and original service standing 5184, standing
raw is 49735. Original callback admission adds 63067 (112802 total). Its command
phase retains 5723 callback raw plus parent 32768 and child 41548: 129774 total.
A native command without a callback uses 124051. No standing ticket disappears
from these totals. The source readiness check also rejects a service allocation
below the source parent+child storage total. Larger caller reservations can still
refuse; they are never silently resized.

## Evidence still required

Retained SDK `sdk.mjs` SHA
`d768bb75542ea853a66c570bd82b010a7b843f4949ab3ebb20e9d1f2a27af881`, two
1100-byte ranges at 950450 and 966802, supports SDK-side `mcp_message` routing
and `mcp_response`. It is partial source evidence, not complete transitive source
or selected native executable compatibility. No runtime package was acquired,
resealed or replayed for this implementation.

The original 9500 selected-input ceiling charges task+hook input and every
native-rendered tool result, including errors and repeats. The MCP response's
bytes are NOT an equivalent measurement. `remaining_selected_bytes` is only the
controller's local budget; the 32000 per-result ceiling and 4MiB transport ledger
do not establish 9500 fit. `SessionStreamRetention` records bytes/digests but does
not persist authenticated per-frame timing rows. `EvidencePublication` is source
custody only and ungraded. Root's incremental `measure_lines` evaluator prepares
a separate qualification seam; control filtering, native correlation, timing
custody and bounded integration are still required. No source-ready or fixture
success state implies that qualification passed.

Real runtime selection, dedicated whole-campaign capacity, two complete weekly
21-case/126-attempt/1900-distractor runs, independent changed-pair grading and
branch automation remain required. The inert tests exercise authored processes
and source mechanics only; they use no original cases/oracles or vendor model.

Cancellation drives the original command CANCEL/wait/RELEASE protocol before
stopping the service. An abandoned command with unobserved stdout/stderr EOF
produces unknown RELEASE: the bank remains quarantined and quotes remain held.
Service interruption enters its owned cleanup through SIGINT; original deadline
escalation remains unchanged. This is not clean completion or a traffic refund.

The focused whole-bank regression completes three callback command exchanges
through the original RPC/service state machines while holding this preparation,
session and service standing storage. At command four it retains 451MiB working
before trying to allocate the 64MiB child ticket. The proposed 515MiB (plus raw)
refuses. This is a full-workload blocker, not a three-command replacement rule.
The original search/expansion allowances are unchanged.

The next custody correction belongs to `CallbackPhases.retain_command_working`
and `before_status`, `ProducerRPC._text`, `_refuse`, `_retire_operation` and
`ReadCustody.observe_completed`/`_publish`. Each successful command currently
transfers its entire 64MiB parent quote cumulatively into the callback ticket.
`_retire_operation` then clears RPC result/request/wire/chunk fields and calls
`CommandOperation.retire`; `ReadCustody` retains normalized offer metadata and a
reference to the retired operation. The source must establish which decoded
strings/graphs, returned pending requests, sender chunks and exceptional frames
still borrow the result at that returning-frame boundary. Producer-side decoded
responses/engine state also need their own lifetime proof under the already held
client/producer working allocation. The adversarial phase fixture intentionally
keeps result and request aliases, so it cannot justify refunding them. A fixed
source path with bounded retained metadata, ended aliases and separate
failure-path quarantine is the correction to investigate; this candidate does
not implement or assume that proof and does not lower a quote.
