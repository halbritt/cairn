# Prospective coding launch declaration

`scripts/trial_coding_launch.py` compiles the reviewed native coding interface
for the future external supervisor. It starts no process and changes no current
harness route. Model and effort are supplied from a frozen request; they remain
declarations until the owner checks the actual init and serving route.

The declaration fixes six builtins, Cairn search/pull only, `dontAsk`, suppressed
permission prompts, isolated settings sources and eight native turns. It selects
the reviewed `implementation/1` permission object. The future owner mounts the
binary and complete reviewed settings/MCP files at the fixed paths, disables
dynamic tool search, and composes the hooks and MCP ceiling separately. Settings
must match the request's permission pin; this module does not authenticate that
request or validate a serving account.

The input contains exactly one JSON user message. The owner must finish its
delivery and close stdin. Extra queued messages can renew the native turn limit.
The original 9500-byte input allowance covers that wire message, the memory
instruction, the existing 512-byte reserve, and the remaining hook allowance;
fewer than 1000 hook bytes refuses preparation. Final answer, MCP byte/call,
hook timing, cost and wall limits still require the reader and external owner.
The USD 4 budget remains an estimate, not an enforcement claim made here.

Before runtime use, freeze the task-specific final keys and reader profile,
verify its exact init surface, bind actual capture/terminal/custody observations,
and retain the runner-owned work product. A mandatory in-profile command denied
by native permission matching is a non-VALID control failure. An actor-selected
command outside the reviewed profile remains actor evidence. No declaration,
prepared settings file or standalone receipt establishes runtime admission,
task success, separate-account capacity or measured usefulness.
