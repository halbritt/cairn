# Paired implementation permission profile

`trial_task_permissions.settings_permissions(profile="implementation/1")`
adds `git add`, `git commit` and `make contract` to the existing prospective
rules. The implementation prompt requires a committed work product and an
updated API contract. The default `existing/1` rules retain their prior values;
an unknown profile is refused. The command observer classifies these operations
without retaining their arguments.

This function constructs settings. It does not execute commands, authenticate a
request, enforce path confinement, select the native tool surface or admit a
provider call. The paired runner must explicitly select and hash these settings
after reviewing the request, then enforce the actor's writable workspace and
the separate evaluator and oracle mounts. A label in an untrusted request does
not establish those facts.

The current prospective executor still uses the default. Adoption belongs to
the reviewed paired runner; no provider route is enabled by this source change.
Before an implementation cell starts, its prompt, native profile and permission
settings must agree. Existing memory-write denials remain part of both profiles.
The native result and action observer must retain actual denials rather than
assuming that a configured rule proves permission or successful execution.

The runner exports committed, uncommitted and untracked selected work after
verified termination and containment release. A missing actor artifact is
incompletion; a missing or uncertain runner export is an evidence failure.
Neither command metadata nor an actor's claimed exit code proves a check ran.
