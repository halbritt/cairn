# Semantic transition fixtures and Release handoff

S-05 / CAIRN-328 supplies a disposable transition harness and this runbook.
The controlling requirements are the transition row and
[Packaging, index transition and rollback](plans/hybrid-runtime-contracts/semantic.md#packaging-index-transition-and-rollback).
Release owns installed configuration writes, activation, rollback and retention.
This document grants no production action.

The default executable fixtures use the actual Go indexer, supervisors, combined API
and a private PostgreSQL cluster with pgvector. Their workers are deterministic
Go protocol fixtures with explicitly artificial identities. They test
scheduling, process ownership, source freshness and completion refusal. They
do not execute a Python model, qualify Rust numerics, or accept a Python rollback.
S-04R / CAIRN-355 acceptance, S-04 / R-01 host qualification and the real-worker
matrix below remain prerequisites for full S-05 acceptance.

## Run the disposable fixtures

From a checkout containing this slice:

```sh
python3 -I -B scripts/check_semantic_transition.py \
  --artifact-dir "$HOME/.cache/semantic-transition-run-$(date +%Y%m%dT%H%M%S)"
```

The output path must be new. The host orchestrates the unchanged
`scripts/test_hybrid_runtime_operations.py` wrapper and retains its command,
isolation report, result and artifact archive. Inside that wrapper the harness
builds a race-enabled Go test executable and the real API binary, initializes
a private PostgreSQL cluster with no TCP listener, and runs the selected tests.
Each database is generated by and dropped by its fixture. A normal
`CAIRN_TEST_DATABASE_URL` cannot select a database for these tests: they also
require the harness's owned-cluster marker and exact private socket path.
No installed semantic source, venv, model, native library, service or database
is mounted as a fixture.

`artifacts/tests.jsonl` retains individual Go test results and observations.
`artifacts/report.json` lists the ten matrix cases, all selected passes,
failures/skips, built executable digests and the real-worker qualification
blocker. A skipped case cannot pass the harness. Failures retain their original
logs. PostgreSQL stops on success or failure; the namespace owns any remaining
fixture children. Lease-expiry/backoff fixtures change timestamps only in this
private database so they do not wait two minutes or five minutes. The production
90-second document, two-second retrieval and two-minute lease limits are unchanged.

## Explicit local real-worker case 1

A separately authorized local dispatch can run retained Python -> BLAS-2 Rust ->
the same retained Python across three collections, using the existing case 1,
combined API, disposable cluster, coverage checker and writer fence:

```sh
python3 -I -B scripts/check_semantic_transition.py --real-case1 \
  --artifact-dir /absolute/new-local-case1-artifacts \
  --python-selection /absolute/s04r/qualified-selection \
  --rust-fixtures /absolute/retained-rust/observed/fixtures
```

The host enters only the unchanged common wrapper. The retained Python stage is
read-only at its qualified `/opt/s04r-selection` guest root, through real fixed
control paths. Ambient locale/gconv data is masked as in its qualification.
The unchanged Rust stage is copied as data into its original private absolute
layout. Safe tar exports omit directory modes, so sealed-format modes are
restored only on this private copy. Member hashes, fixed launcher bytes and ABI prerequisites are
checked. Neither package nor control generation is re-derived.

Case 1 records the full active-current-version source population/hash, coverage
and failure/backoff denominator. Every direction stops and joins the previous
combined API and worker groups and disables all test-owned restartable writer
definitions before checking the fence. Publication audit includes model, source
version and body hash. This controlled inventory is not a managed-host roster.

Selected worker traces follow clone/fork descendants and exclude legitimate Go
API/database traffic. Missing descendant traces refuse the proof. Positive
controls check failed-connect and store-write detection. Actual Python mapped
bytes/environment and Rust sealed native images are observed. Private worker
HOME/cache must remain empty. Both Python identities must restore exactly.
The traced root PID set for each implementation must exactly equal its sampled
mapped-byte/environment PID set; one missed worker refuses the proof. Run the
observer unit tests through the same common wrapper:

```sh
python3 -I -B scripts/test_hybrid_runtime_operations.py -- \
  /usr/bin/python3 -I -B scripts/testdata/test_semantic_transition_real.py
```

Whole-API and semantic outage windows, first API query, rebuild completion and
post-rebuild query are separate observations with retained timestamps. Forward
and reverse windows start from the last observed healthy old service; initial
startup begins with semantics disabled. They are sampled windows, not a claim
of continuously measured availability. The first query can report unavailability while the
asynchronous index initializes; this is not a forced cold query-worker restart.
Identity probes while the API is stopped are included in observed outage.
Product deadlines stay unchanged; the outer fixture budget accommodates real
work. No zero-outage or fleet-capacity claim follows.

Case 1 acceptance does not close the other real-worker cases or declared subcases,
including forced query-worker restart, failure populations and the Release handoff.

## Explicit local real-worker case 3

The bounded death/deadline dispatch reuses the same exact retained selections:

```sh
python3 -I -B scripts/check_semantic_transition.py --real-case3 \
  --artifact-dir /absolute/new-local-case3-artifacts \
  --python-selection /absolute/s04r/qualified-selection \
  --rust-fixtures /absolute/retained-rust/observed/fixtures
```

Four subcases cover Python death, Python earlier caller deadline, Rust death and
Rust earlier caller deadline. Each uses actual `CommandEmbedder` and
`OpenIndex`/`Step`, three ordinary sources across three collections and a fresh
private database. Direct `Step` calls retain the actual `worked` and error
values. The common wrapper, fixed guest roots, launcher/identity checks,
pre-execution inventories, native mappings/environment samples, exact traced
root/sample equality and worker-tree effect checks remain mandatory.

The harness first completes a short ordinary document on the actual lane and
records its supervisor-owned process pointer and verified native-runtime PID
receipt. A private table lock then holds `Step` at its source read after its
autocommitted lease is observable; `pg_stat_activity` must confirm that wait.
This removes a race where cold inference could finish before its runtime sample
arrived. The lock changes no source rows or product code and releases immediately
after the PID fault. Thus the fault precedes that Step's document exchange on a
previously healthy lane, rather than claiming interruption inside inference.
The fault requires both the live lease and verified receipt.
The harness proves descent from its own Go test process and targets only an
owned positive PID greater than one. Death sends `SIGKILL` with a live caller;
the deadline branch sends `SIGSTOP` and waits for its genuine 30-second caller
deadline, earlier than the unchanged 90-second document limit. The supervisor
performs its normal cancellation/reaping. Ownership and unsafe PID/signal tests
intercept all process control. Case 3 binds the lane directly through
`CommandEmbedder.document.worker` after the healthy warmup, plus canonical
launcher trace and ownership checks. Case 2's L1 startup-order inference remains
unchanged. This is not an inference-frame observation or a maximum-document or
latency experiment.

A failed operation must report `worked=true` and a non-nil error without any
publication. The deadline branch must preserve `context.DeadlineExceeded` from
its expired caller; death must persist one attempt and future backoff with a
live caller. An expired caller may retain its original lease because retry uses
that same expired context. Full queue rows and an OLD/NEW job audit preserve
that distinction. Source rows, full completion/failure denominator, worker exit
trace and reap, observed stdout write prefixes, and the discarded document
worker/reader are retained. `CommandEmbedder` exposes no embedding cache
protocol; this does not qualify the separate streaming rank cache.

After the active call joins, the owner closes both lanes and the index, disables
its test-owned restartable definitions and proves its local fence. Only the
failed row's private `lease_until`/`retry_at` timestamps are made due. Lease IDs,
attempts, other jobs and source rows stay intact. One restart with the same
exact generation must complete all three sources with current model, version,
body hash, valid passages and finite nonzero vectors. Audit checks refuse
reinsertion, erased attempts, stale or duplicate publications. Unresolved rows
remain in every coverage report.

`real-case3-{python,rust}-{death,caller_deadline}.json` and `real-case3.json`
retain the four results. Focused ownership tests run through the wrapper with
`go test ./semantic -count=1 -run '^TestSemantic(Restart|Failure)OwnedPID$'`;
the observer tests are `scripts/testdata/test_semantic_transition_real.py`.
The deterministic ten-case/32-entry/no-skip regression is unchanged. Case 3
leaves seven other real cases, full S-05 and all numeric/runtime/fleet/production,
controller/retirement, R1, CPython value-graph and RTERM1 holds open. It grants
no ticket closure or installed action.

## Population and completion gate

Use a consistent database snapshot of **every active record's current version
with `payload_deleted_by IS NULL`, across all collections**. Query-scope
eligibility is not this completion denominator. For every source require:

- Exact record ID, current version and SHA-256 of the original UTF-8 body.
- The selected embedding derivation identity in `semantic_document`.
- Between 1 and 256 passages, with ordinals exactly `0..n-1`.
- Positive in-bounds spans whose original body byte slices are valid UTF-8.
- Exactly 384 finite vector components and a finite, nonzero norm.

The test-only checker in `semantic/transition_acceptance_test.go` independently
reads these facts in a repeatable-read, read-only transaction. It retains every
unresolved record ID/reason and the queue's attempts, retry time and lease state.
Final evidence also needs the writer/source-mutation fence: a snapshot does not
prove that the state will remain current after that snapshot.

An earlier caller deadline can leave its lease in place because retry scheduling
uses the expired caller context. Retain and report that lease until expiry;
do not assume every failure immediately produces an unleased retry row. The
fixture advances that private lease before testing recovery.

Blank, token-empty, otherwise unembeddable, failed and backed-off records remain
in the denominator. The whitespace negative is an explicitly constructed
retained database row; ordinary Create rejects it. Never delete, re-scope or
silently exempt those sources to obtain a full-coverage result. Empty queues,
zero live leases, successful queries, ready state and document-row counts are
insufficient. Partial dense coverage does not promise lexical fallback for each
missing vector.

`OpenIndex` currently seeds by missing current-version/model document. It does
not re-seed a current-version/model document with a wrong body hash or missing
passages. The negative fixtures expose this distinction. If an installed
derivation fails this audit, stop the full-completion claim and request a
separately authorized derived-state repair. This test-only slice changes no
production seeding, schema or repair behavior.

## Release inventory and fence

Before either direction, record the database identity and all writer definitions
that can reach its database-wide `semantic_job` queue. Include the combined API,
alternate collection configurations, inactive/restartable units, socket/timer
activation, containers, supervisors and manually launched indexers. Record
definition/configuration/launcher digests, mode, model identity, current process
and child ownership, restart/activation policy and who owns the stop. Retain
selected connection identity without passwords. Unknown/unreachable writers are
gaps. A collection-specific service name is not a database-wide exclusion.

Release first prevents old definitions from restarting, stops their owners,
and joins indexer goroutines, active calls and both worker lanes. Record process
exit/reaping and owner completion before starting another generation. The
fixtures call the existing `StartIndex` close, verify fixture child PIDs are
reaped, and audit every document insertion in a disposable trigger table.
They refuse a fence while a second collection's writer or an inactive
restartable definition remains. This controlled inventory does not certify a
real host's inventory.

Apply the same steps on reverse selection. Lease expiry, an empty queue or an
idle child is not stop/join proof. Do not start the new generation while an old
owner can still publish or restart. Do not substitute overlapping generations
or change schema to avoid the fence.

## Configuration delta and rollback

The default remains unchanged: with no semantic option, `serve` selects no
semantic worker. Prepare a before/after configuration artifact for Release;
do not write the shared installed configuration from Semantic.

For S-04's **fixed, zero-argument launchers**, retain the same service mode and
replace only the selected absolute immutable launcher path:

| Selected mode | Existing `cairn serve` option, for either fixed Python or Rust launcher |
| --- | --- |
| rank | `--semantic-command /absolute/immutable/launchers/ADDRESS/rank` |
| stream | `--semantic-stream-command /absolute/immutable/launchers/ADDRESS/stream` and the existing idle timeout |
| embed | `--embedding-command /absolute/immutable/launchers/ADDRESS/embed` |

Do not pass a fixed zero-argument launcher as `RustWorkerConfig.executable`:
that separate raw-binary route appends asset arguments. The disposable matrix
also exercises `StartRustIndex` with a labelled protocol fixture to cover that
existing route; placeholder assets in that case qualify no native library.
No flag default, mode, timeout, thread cap, environment, model or tolerance is
implicitly changed by this handoff. Select no mutable `current` symlink.

After the joined fence, Release selects the exact new path and restarts the
combined API. Observe whole-API unavailability independently of semantic
unavailability and partial coverage. Record the last successful nonsemantic
API probe, stopped interval, first successful probe, selected worker startup,
cold query-lane behavior and full rebuild completion. Fixture timings are
local scheduling observations, not production availability guarantees.

Before cutover, retain the exact Python interpreter/venv, worker sources,
prepared model/config, native libraries, launcher bytes and pre-cutover rank
and embed identities. Reverse selection restores those exact accepted bytes
and both identities after stopping/joining Rust writers; it then performs and
audits the full database-wide reverse rebuild. A previous Rust generation or
a fresh dependency installation is not the Python rollback closure. Retain
operational source data and the Python closure until Release retirement gates
permit otherwise. No zero-downtime, instant rollback or full-coverage claim
follows from a successful restart.
