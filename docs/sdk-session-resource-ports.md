# Original resource ports for the SDK session

`SDKSessionDriver.from_resources(preparation, binding)` requires an
`SDKSessionResources` binding and a preparation carrying the same original
attempt ledger. Bound preparation cannot fall back to the legacy session
constructor. The binding supplies the existing unlaunched native owner, an
already-held operation allocation and DATA stream. It is claimed before pump
slabs and writer construction; the original controller and source custody move
once. No owner, ledger or allocation is replaced during construction.

`SDKSessionResources` specializes the existing producer receipt I/O port rather
than duplicating its stream arithmetic or EOF rules. Its named local minimum
covers stream slabs, bounded writer copy, decoder copy/concatenation and UTF-8
carry only (`5 * 512 + 6`). It is not a complete preparation/session quote.
Controller/callback graphs, encoder scratch, suspended decoded text, output
custody, Python overhead and native processes still need explicit original
allocations. Positive working bytes or this named minimum never grants admission.

The writer caps both pending-suffix copy and syscall offer by available credit.
Every selected read/write pledges against the same original traffic bank and
reconciles the exact original owner's fresh receipt before the pump hashes,
parses or checks its next clock. Stderr may consume capacity selected earlier
in a poll; the following write recomputes its allowance. Unknown receipt or
later failure quarantines accounting while retaining the known positive prefix.
Resource boundaries also cover interrupted final local cleanup.

When credit is parked by promises/protected future responses, payload read/write
interests are suppressed and wait observation remains available. The inherited
EOF-only probe is eligible only at genuinely exhausted capacity with no pending
or future promises; it grants no payload byte. Callback stdout loans remain held
through reply_written. A single DATA stream belongs to this native domain;
producer domains retain their own streams in the same bank, never separate
per-child limits.

Normal close retains allocations and stream commitments. It is not evidence
that borrowed launch/controller, decoded graphs or all other aliases died.
The original trusted attempt owner still owns actual stop/wait/cleanup and final
charge release. Full quotes, source-origin/native dispatch, fair coordination,
physical fit and runtime admission remain unproved. This candidate has only
synthetic-file/inert-syscall validation and requires independent review.

Resource recovery preserves the primary exception if ledger freeze fails. The
binding becomes locally unavailable and retains fixed `resource_cleanup_faults`
codes; a failed freeze does not imply that the shared bank is frozen. Constructor
cleanup still attempts both native-owner and source-owner release. Allocations
remain held. Every public step/reply checks the exact standing allocation before
I/O, including operations after the first step.

Claim guards are local to each binding wrapper. The trusted builder must issue
unique bindings for the owner/allocation/stream combination; this interface does
not enforce uniqueness across separately constructed wrappers.
