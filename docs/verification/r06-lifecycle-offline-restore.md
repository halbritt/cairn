# Retained Python /2 cold restoration

This finite fixture preserves the genuinely selected `/2` literal Python argv.
It does not use a `/3` compatibility receipt or change its verifier. The real
`OwnedUnit.stage_legacy` producer and unchanged strict retained inspector supply
the complete 17-member engine, bridge, binding, configuration and argv selection.

Before freezing the argv, the fixture copies the current approved interpreter,
standard library, mandatory installed `websocket-client` package and distribution
metadata to a private runtime prefix. CPython uses its unchanged
prefix discovery. There is no interpreter patch, wrapper, `PYTHONHOME`, download
or alternate environment used to find packages. The selected profile must have
only paths beneath that owned prefix. A copy of the pinned lifecycle API CLI and
a declared synthetic selector with the same interpreter and `-IB` shebang are in
the payload; the actual restored memory engine performs its real authenticated
Store calls.
The engine's disposable application state also owns its temporary selection
directory. Its working-directory environment matches the actual fixture cwd;
the normal host `HOME` and `PATH` remain intact.
The selected interpreter, CLI and all archived Python extension modules have
their installed ELF dependency closure copied into the asset. Child-only
`LD_LIBRARY_PATH` selects those exact private library bytes before freezing and
after restoration. The unchanged ELF interpreter retains its fixed non-retired
OS loader anchor; its identical loader bytes and provenance are also archived.
The fixture does not patch that interpreter or change its selected argv.

The offline archive and its full path, hash, byte, mode and owner manifest are
outside the retired destination. The fixture removes only its own selected
runtime, records initial absence, restores into the exact same absolute paths,
and independently verifies the entire restored tree before launch. The trusted
runtime check belongs to the restoration controller; it does not add a new
verifier to the retained argv. The original `/2` loader keeps its own checks.

Run focused archive checks and the actual disposable fixture through mise:

```sh
mise run test:unit -- scripts/test_r06_lifecycle_offline_restore.py
mise run host:exec -- --timeout 10m --weight 2 -- python3 -B \
  scripts/check_r06_lifecycle_offline_restore.py \
  --images /absolute/pinned/images-host.json --evidence /absolute/new-private-run
```

After cold restoration, the mandatory package must import entirely from the
sealed prefix, report the pinned distribution version and exchange a real
WebSocket frame over a local socket pair. Its imported module origins and loaded
ELF mappings must belong to the restored closure, apart from the declared fixed
OS loader anchor. This proves offline package availability alongside the real
lifecycle effect; it does not count as that effect or as a native-client test.

The actual restored ordinary Claude `SessionEnd` capture must save one memory
record in a new private API/PostgreSQL fixture. The disabled `/2` inbox binding
keeps ordinary profile validation and rejects enabled-required validation using
the existing bridge API. Its retained presence path must reject the synthetic
native event with the exact `INVALID_HOST` diagnostic and leave sessions empty.
The existing `CAIRN_COORDINATION_DISABLED=1` switch separately preserves the
coordinator's `{}` no-op. These controls do not prohibit ordinary memory capture.
Numeric exits, exact streams, before/after Store readback and file/exec origins
are retained. Traces contain file names and process calls,
not read/write buffers or credential contents. Profiles and token files remain
in the disposable application state and are excluded from the offline payload.

Missing, tampered, mixed-member and unsafe-mode interpreter, websocket and native
library members refuse before launch. The unchanged retained
inspector rejects mutated version, foreign-reference and wrong-binding inputs.
These three binding mutations hit its generation-member hash check; they do not
independently qualify deeper semantic rejection after a newly authenticated pin.
Each control restores the exact selected bytes and modes and preserves the
Store state. The unchanged `/3` verifier must also keep its exact refusal of an
intentionally negative `/2`-schema diagnostic receipt. This diagnostic does not
create a `/2` compatibility receipt or modify either selected literal vector.
It runs on the collector's declared host interpreter, separately from the
restored `/2` role and helper subprocesses. Collector process receipts record
the actual subprocess argv and numeric exits without replacing product APIs.
Unit checks cover archive corruption, destination changes,
foreign declared ownership, traversal, unsafe modes, extra files and links.

Scope is Linux x86_64, the recorded non-retired base-OS ABI, and this supported
ordinary capture row. Dynamic OS libraries, process/device metadata and OS
configuration are declared separately from retired Python/runtime dependencies.
Source symlinks are copied as regular bytes, with their original link targets
and resolved source hashes recorded separately. Ancestor path ownership/link
metadata checks are reported separately from file or directory reads.
The fixture makes no native-client, model-account, other-harness, semantic
reverse-rebuild, all-host M05, common-image, HC05 or production acceptance claim.
