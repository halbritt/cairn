# Native MCP configuration task and follow-up, 2026-09-08

A fresh OpenCode run retrieved a revised Cairn procedure and produced a usable
MCP configuration after an earlier run produced an unusable one. Both runs now
have native retrievals associated with actual host attempts, process outcomes
and separate task assessments through the existing API.

This is one operational correction-and-reuse result. It does not establish a
causal advantage over no memory or direct context, general recurrence reduction,
coding-task improvement or native Striatum ingress.

## Task and observations

The task requested an OpenCode 1.18.21 configuration for the existing Cairn
installation, with explicit executable/socket/ordinary-token/repository/task/run
values, search and body-pull permissions, no provider or database credentials,
and citations to full memories actually inspected. The model had only native
Cairn search and body-pull tools. The launching host held observer authority.

| Observation | First run | Fresh follow-up |
| --- | --- | --- |
| Curated MCP procedure retrieved | Version 1 | Version 2 |
| Successful native searches / body pulls | 1 / 2 | 1 / 2 |
| Process exit | 0 | 0 |
| Independent OpenCode discovery exit | 0 | 0 |
| Requested server connected | No; discovery reported no configured servers | Yes; discovery listed Cairn connected |
| Retained task assessment | Rejected | Accepted |

The first run initially supplied an invalid search UUID, received a tool error
and recovered with a valid UUID. It then generated a string `command`, separate
`args` and per-server `tools`. Native discovery did not configure a server. A
zero exit therefore proved neither task acceptance nor a working configuration.

The host checked the correction against the existing setup guide and actual
OpenCode discovery: `command` must be an array; permissions belong at the top
level and use the prefixed native tool names. The original candidate was retained.
Those selected, verified details were added as version 2 of the existing ordinary
procedure. No raw session was captured and no authority promotion was performed.

The follow-up used the same task prompt in a fresh model session. It pulled the
exact revised procedure and connection lesson, cited both, and produced the
requested command array and permissions. The host checked the complete object
against the requested values and ran discovery against the unmodified generated
configuration. OpenCode connected. The resulting configuration remains outside
Git as an operator-reviewable artifact; no global harness configuration was changed.

The prompt preceded both runs. A detailed review checklist was written after
the first run completed, before its output was inspected. This is an exploratory
before/after observation, not a blinded or controlled experiment. The
[metadata](mcp-host-use-2026-09-08.json) records identical prompt hashes, binaries,
request counts and descriptive timings; these do not establish a speed advantage.

## Host association and deployment

The existing `TrialHost`, bounded relay, process wrapper and bubblewrap were
used. Only the ordinary agent token was mounted into the model environment.
The bootstrap query selected no task memory; the observed memory exposure came
through native MCP calls. The host associated each successful search receipt
with its run using `link-run-retrieval`, with an identical retry checked.

Operator reports now show procedure v1 and the connection lesson expanded under
the rejected task, and procedure v2 and the connection lesson expanded under
the accepted task. Other indexed records retain unknown usage. The reports
retain one execution per run, one linked retrieval each, zero-exit process
outcomes and separate versioned task assessments. Final citations were inspected
independently; they were not converted into a stronger persisted usage signal.

A dedicated hosted observer profile was provisioned for these actual host runs.
The existing local observer and ordinary agent profiles were retained. The API
was restarted to load the new profile and now runs the installed `cda6762` build,
SHA-256 `e2b67b2b7061db1991f2d25ebe58e5b61ab57d80f26137f4d6be3da7ed4ab3e9`.
No store migration or new production API/code was needed. Hosted observer
`use-report` access remained denied; inspection used the existing operator CLI.

Both model runs, wrappers, MCP children and relays are terminal; isolated model
homes/configurations were removed. Private prompts, outputs, record identifiers,
association requests, assessments and generated configurations remain outside Git.
The reusable procedure revision and observed run records remain in Cairn.
