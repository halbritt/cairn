## What changed

The [build-input implementation](native-build-input-2026-09-08.md) already resolved
a packet-named Cairn observation into a sealed input and rendered its complete
context. The supervisor now checks that input against the actual backend
declaration, agent runtime, destination and optional staged base/revision pins.
It confirms the retained package through its owning observer profile, binds its
own live process incarnation, and claims once before calling the existing
confined-process launcher.

The supervisor records supplied prompt availability, acknowledged service
observation IDs, process exit/timing and separate stdout/stderr digests. Its
committed submission retains those facts alongside the exact receipt, input,
dispatch, manifest and prompt correspondence. Admission checks the retained
host attestation against the package, input and invocation. It does not contact
Cairn to authenticate reported service IDs independently.

An ambiguous or refused claim prevents child creation. Native internal relaunch
is refused because the retained receipt permits one invocation. Exit zero with
missing required outputs is recorded as `no_result`. A committed complete output
set can be recorded as `completed`, which still does not mean compiler admission
or task acceptance. Recording errors remain visible without automatically
launching again.

Trusted host configuration selects the repository's observer profile; the
provider receives no connection paths through its prompt or manifest. Inherited
`CAIRN_*` and `STRIATUM_CAIRN_*` environment values are cleared for the child.
This checks environment handling, not complete filesystem isolation from host
credentials. Existing backend confinement still governs process access.
