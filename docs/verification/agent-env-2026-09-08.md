Cairn's installed client now accepts explicit `--socket` and `--token-file`
paths with both HOME and CAIRN_HOME unset. Each omitted option still uses its
normal default. Empty explicit paths return `INVALID_REQUEST`; a bad explicit
token path cannot silently select another identity. The agent path continues to
use the authenticated Unix API without opening the operator database.

API kept PID 3421974 and its previous binary; this client-only fix required no

## What the experiment actually established

The experiment was frozen in `0e7d8ccd326432189cb8cbf774da4064228d1ac1` before
model execution, using source `45e37cf`. The
[preset and gate](../../trials/agent-env/README.md) compare the same real defect,
source snapshot, OpenCode/model binding, tool permissions and per-arm allowance:
16 requests, 8,192 output tokens per request, 300 seconds, one attempt each.

The supplemental material was the exact earlier reviewed `exec.Cmd.Env`
override-order lesson, not a lesson authored for this task. It was supplied
directly in one condition and copied as shareable A memory into an owned
disposable repository for retrieval in another. The original lesson stayed
local and unpromoted. Its mechanism differs from CLI default resolution;
relevance was explicitly uncertain before execution.

All three hit the **local experiment request allowance**, then OpenCode retried
the resulting HTTP 429 six times before exiting. None met the frozen completed-run
acceptance criteria. Each candidate passed all 11 behavioral cases in the hidden
gate. The per-arm Go suite ran without a test DSN, skipping 193 database tests;
full integration testing was separate and used the final reviewed repair.

The retrieval condition made **zero Cairn searches and zero pulls**. Its earlier
host preflight successfully retrieved the exact lesson, but that is not model
contact and was not linked as model use. No dynamic retrievals were linked to
any of these model runs. This trial therefore **did not test lesson transfer**.
The baseline independently found a functional repair; memory cannot be credited
for the integrated fix.

The original controller also incorrectly recorded allowance exhaustion as a
task-domain rejection. Those v1 assessments remain in the original dump. A
separate review of the retained actual API errors and relay counters wrote v2
assessments in an owned disposable copy: `task_outcome=unknown`,
`failure_domain=binding`, `failure_kind=quota`, supported by new evidence. Original
candidate checks and process outcomes were preserved. The controller now uses
that distinction; unclassified nonzero exits stay unknown. Neither correction
turns a run into an accepted task or establishes model capability failure.

Costs are the provider's reported per-request values, available for all 48
requests, totaling $0.030681837328. They are not a comparative efficiency result:
no run completed normally and the retrieval treatment was not exercised.

## Limits and next action

The constrained snapshots omitted referenced build/documentation files, and
models spent calls looking for some of them. The small request allowance and
missing-file distractions limit interpretation of the run failures. The lesson
was also weakly related to the repair. Do not repeat this preset until it passes
or treat the results as evidence against useful memory generally.

Use existing retrieval in a real authorized build with a task-relevant memory,
a complete usable workspace and explicit observation of actual tool contact.
That is a better next step than adding storage/recovery machinery or another
trial whose treatment never reaches the model. Native Striatum ingress and
cross-harness benefit remain open.
