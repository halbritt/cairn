# Explicit browsing through agent interfaces

Agents can now inspect eligible memory when they do not know its vocabulary:
`cairn agent search --browse`, or `cairn_search` with `{"browse": true}` in MCP
and native OpenCode. Returned entries retain their ordinary pull arguments.

## Motivation and scope

The unchanged development workload still exposes lexical misses on ranker v4.
In a fresh run, `storage?` returned no notes in either insertion order. The
storage-location question placed its answer eleventh or fourth in the index.
These are the previously authored questions and labels, not a fresh benchmark.

The core already supports an empty-query index, with scoped eligibility,
mandatory context, destination filtering and ordinary packing. The CLI and
native tools rejected that query, leaving this discovery route available only
through lower-level request JSON. The new option exposes that existing behavior.
The ranker, compiler, store schema and sealed package format are unchanged.

Browsing requires an explicit option. Missing search text without that option,
or combining browsing with query text, is refused. Queries that find nothing
continue to return their original result. The alternative of changing ranking
would require separate evidence for vocabulary recall and precision; this change
does not attempt to resolve those problems. Leaving the interfaces unchanged
would preserve the need to construct raw index requests for browsing.

## Verification and actual limits

The full disposable PostgreSQL/API suite passes with native OpenCode enabled.
CLI and MCP tests retain mandatory context, scope and destination while browsing;
MCP and native OpenCode exclude local-only notes from hosted results and pull the
intended record through the returned handle. Invalid query/browse combinations
are rejected. Existing search, capture, edit, evidence and permission checks pass.
`make check` and `make test` also pass, including 26 Python tests.
The normal-session scripted check also confirms that a string `browse` flag is
rejected by the adapter's runtime validation before connection access.

The candidate CLI and adapter are installed locally. Actual OpenCode 1.18.21
custom-tool execution and a fresh Codex CLI 0.153.4 MCP client each browsed and
pulled a saved note using native session scope. These were explicit client calls,
with no model inference. No service restart or database migration was needed.

The operational CLI check returned six previews and reported three packing
omissions at the configured 32,000-token input room. The older storage note was
among those omitted. An explicit CLI request with 64,000 tokens returned all nine
eligible previews, including that note. Both figures use the conservative byte
budget; they are not tokenizer measurements. Native configurations remain at
32,000. Browsing is a bounded topic preview, not a complete inventory, and it
does not guarantee discovery of older notes. There is no pagination in this
interface. A narrower query remains the way to retrieve beyond the preview.
This describes the original 2026-09-09 interface; the later
[browse paging check](browse-pages-2026-09-09.md) adds pagination.

The [manifest](browse-2026-09-09.json) retains source/binary hashes, the current
lexical measurement, integration logs and installed-client observations.
Operational note bodies stay in private local artifacts.

This adds a usable discovery path across interfaces. Better task outcomes,
independent model adoption and a controlled memory advantage remain unproved.
