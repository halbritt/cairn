# Ordinary note edits through MCP, 2026-09-08

The native configuration correction-and-reuse trial required a saved procedure
revision between runs. The ordinary Unix API and raw `cairn agent edit` already
supported that operation, but MCP exposed only search, body/evidence pulls and
capture. A harness confined to those tools could create another note but could
not revise the existing one.

`cairn_edit` now forwards the existing ordinary edit request. It requires the
record ID, expected version, stable request UUID and complete replacement draft.
The facade rejects a different repository before calling the API. The core owns
active-A eligibility, exact version and retry checks, fixed scope/sensitivity/
applicability, and writer stamping. The response contains only record ID, new
version and request ID. It never echoes a local body after a write.

Using the existing complete draft contract avoids a read-then-edit convenience
path whose retries could accidentally depend on a later version. A caller must
copy the intended draft fields from its pulled record and reconcile conflicts.
An independent review, automatic correction, authority promotion or successful
downstream task is not implied by an authenticated edit.

## Verification

The Go SDK integration against a real Unix API and disposable PostgreSQL checks
one revision, identical retry, changed-intent refusal, stale-version refusal,
stored body/writer/class, and no body in the response. It also checks refused
repository, task-scope, sensitivity and pin changes, and B/C edits. Previously
issued pull handles become stale after the successful edit.

An independent JSON-RPC stdio client captures, searches, pulls and edits a note,
retries the edit, and checks stale requests. A fresh MCP session retrieves the
corrected version and exact body. The client has no HOME or usable database
address. `make test-integration`, `make check` and all 17 Python unit tests pass.
The generated memory-only configuration still permits only search and body pull.

No migration, core mutation semantics, profile change or server restart is
required for this facade addition. Installed use is recorded separately below.
